# 助理是怎么工作的：轮次、上下文与记忆

personal-bot 每个账号运行一个助理。它一次只处理一轮，而它在轮与轮之间携带的全部东西，
存放在三个地方：一个滚动切换的上下文窗口、它自己写下的笔记，以及一份只追加的自身行为日志
（每一轮、每次工具调用、每次发送）。这一页列出什么会开启一轮、一轮里会发生什么，以及上下文
和记忆怎么保存，每项只用几句话说明。整套栈的其余内容（容器、面板、沙箱）在 README 里说明。

## 什么会开启一轮

每一轮都有一个原因，面板的日志里能看到：

- **消息。** 私聊消息，或群里 @ 助理、回复它、叫它名字的消息，按该会话的策略开启一轮。
  其他群消息，在助理决定插话时也可能开启一轮（见下文）。
- **唤醒词。** 助理安静地结束一轮时，可以留下几个唤醒词；六小时内，该会话里出现其中任一词，
  不用点名也会开启新一轮。
- **`wait`。** 助理可以说"过一阵再来看"，从一分钟到一天。到点后会话带着最新消息重新打开。
  最多连续等十次；在此之前该会话先开了别的轮，这次等待就作废。
- **定时任务。** 一次性或重复的任务，到点在指定会话开启一轮，任务说明就是这一轮的输入。
  只能在管理员的私聊里创建和修改。
- **空闲轮。** 设定的分钟数内一轮都没有时，助理会得到一轮属于自己的时间，不属于任何会话：
  可以做感兴趣的事——搜索、阅读、用工具、写笔记——也可以什么都不做。默认关闭，间隔在面板里设置。

任何一轮开始都会让空闲轮重新计时；等待和定时任务重启后仍然有效，停机期间也不会积压补发。

## 按批判断与插话

- **一批只判断一次。** 消息会先收集片刻再做决定：同一个人连着发时等得久一些，换人接话时
  等得短一些，被 @ 时最多等一秒，一整批最多约八秒。
- **插话。** 在允许它主动发言的群里，由快速裁判（一个小一号的模型，见下文）判断现在插话是否
  自然；助理刚说过话时，栈会扣一点分，批次里 @ 了它时扣得少一些。只是在跟别人说话的批次不会去接。
- **沉默退避。** 在一个群里连续几批都没开口后，下一次判断会推迟，每次翻倍，最多几分钟。
  期间消息只是暂存、不会丢；有人 @ 它、叫它名字、说出唤醒词，或者消息一下子攒多了，
  都会立刻结束推迟。
- **排队。** 几个会话同时在等时，等太久的那个先处理；快速裁判也可以按紧急程度重排，
  这是一个面板设置，默认只记录它的判断、不生效。

## 一轮之中

- **轮中来的新消息。** 正在处理的会话里来了新消息，会在两次工具调用之间交给正在进行的这一轮，
  助理能看到对话在推进。空闲轮进行时，任何会话里通过了上述判断的批次也会这样交进来。
  恰好在一轮结束时才到的消息，会退回去作为新的一批重新判断。
- **说话是可选的。** 只有助理发出去的内容才会到达聊天；它可以一句话不说就结束一轮。
  每次发送离开前都会检查：说到具体事情要有引用依据，以及什么话能在哪里说。
- **兴趣。** 助理会把感兴趣的内容记进笔记，之后的轮次——一次等待、一个空闲轮、
  一段碰到相关话题的对话——都能接着拾起来。

## 一个会话，滚动窗口

助理在整个账号生命周期内只保留一个会话，但它的工作记忆不是一条无限增长的对话记录，
而是一串上下文窗口。每个窗口有一个 token 预算，窗口在 token - 而不是轮数 -
达到上限时被替换。窗口打开期间，它的开头部分永不改变，这让模型服务商的提示词缓存
始终有效。

## 分阶段提醒

窗口将满时，栈会把提醒追加到窗口的最新部分，而不是缓存住的开头：

- 用到预算的 15 %、30 %、50 % 时：更新笔记；
- 用到 60 %、70 %、80 % 时：另外写一份交接并轮换窗口；
- 在硬上限前不久，还有最后一条提醒。

每条提醒都带着窗口的真实数字（已用、上限、大约还剩多少）、它在系列中的位置，
以及无视它的代价。每条都标明这是栈的提醒，而不是某个人的请求；同一时刻只发送
已跨过的最高一级。

## 笔记：长期记忆

笔记由助理自己写，是它唯一的长期记忆。

- 每条笔记带一段不超过 200 字的摘要，所有列表显示的都是摘要而不是正文——
  这样扫视许多笔记很便宜，正文只在需要时才读。
- 笔记共享窗口的 token 预算：写入在窗口的 15 % 处开始警告，超过 20 % 即被拒绝；
  删减一条笔记或删除一条笔记则永远允许，因为预算拒绝增长，但从不拒绝整理。
- 每个新窗口保留一组活跃笔记——至多 20 条、至多占窗口 15 %——由栈在轮换时挑选：
  先是管理员设定的常驻笔记，然后是旧窗口里写过或改过的笔记，剩下的按实测使用度排序，
  快速裁判可以参与加权。
- 其余笔记全部归档且可检索。笔记是只追加的，并锚定到它引来的消息和操作，
  因此一条笔记被修改之后，依然指向它的出处。

## 轮换

- 助理可以自己轮换：写一份分四项的简短交接——当前话题、进展、待办和约定。窗口用量不到 60 % 时该调用会被拒绝，
  因为轮换会丢掉窗口里的上下文。交接上限约 4 000 token，因为它要开启下一个窗口，
  并留在那个窗口的缓存前缀里。
- 到达硬上限时，栈会自行轮换，且完全不写交接。该窗口的上下文不会被重放。
- 管理员随时可以在面板里手动轮换，附上一条理由，由它开启下一个窗口。

## 新窗口带着什么打开

第一个窗口之后的每个窗口，都以一条固定的开场提示开始，随后是活跃笔记、
交接（如果有）和当前会话的最近消息。上一个窗口的对话记录不会重放，但依然可达：

- 笔记，靠检索和读正文；
- 助理自己的历史——有哪些窗口、某个窗口里发生过什么、某条记录前后是什么；
- 聊天记录本身。

开场提示给出的恢复顺序是：先笔记，然后最后一条锚点附近的消息，再按锚点查历史，
最后才是搜索。

## 快速裁判读的最近上下文

一个小一号的模型——快速裁判——决定何时回复、多个待处理会话按什么顺序进行、
是否引用回复、以及要不要在群里插话。回复内容从不由它撰写。

当某个判断是针对一段对话时，它通过同一个构建器读那段对话：按顺序排列的最近消息，
再加上——当问题关于助理自己的发言时——它最近在那里说过的话。这段内容有界，
约为快速裁判 32 000 token 窗口中的 6 000 token：最早的消息整条丢弃，
一条消息绝不会被切成两半，状态里记录丢了多少条。每个请求在离开前都会抹掉密钥值，
而那些只判断附近上下文的问题不读人格设定。

## 与其他项目的对比

下面的事实来自各项目自己的文档（链接见本节末尾），截至 2026-10-26。

| 项目 | 它是什么 | 上下文窗口 | 长期记忆 |
| --- | --- | --- | --- |
| **personal-bot** | 跑在你自己机器上的单账号助理 | 带 token 预算的滚动窗口、分阶段提醒、带书面交接的轮换；旧窗口始终可检索 | 助理自己写的笔记：带摘要、带 token 预算、每窗口一组由栈挑选的活跃笔记 |
| [AstrBot](https://github.com/AstrBotDevs/AstrBot) | 支持多种 IM 平台的聊天机器人框架 | 按会话管理上下文，在模型窗口的 82 % 处自动压缩：按整轮丢弃（默认），或用 LLM 摘要并保留最近 15 % | 核心不内置长期记忆；另有知识库（检索）存放文档，群聊历史也可注入 |
| [MaiBot](https://github.com/Mai-with-u/MaiBot) | 面向群聊的聊天机器人框架 | 一个最近消息窗口，历史被裁切时由专门模型总结成摘要 | A-Memorix：对抽取出的记忆做向量、图谱和 BM25 检索，默认各聊天流互相隔离 |
| [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) | DeepSeek 的开源智能体框架 | 只追加的会话日志派生出模型可见的上下文；在所路由模型窗口的 80 % 处自动压缩，原样保留最新 16 %；超大的工具输出会先被裁剪 | 不内置记忆；提供连接第三方记忆 MCP 服务端的参考配置 |
| [pi](https://github.com/earendil-works/pi) | 本项目所基于的 TypeScript 智能体框架 | 会话存成一棵只追加的树；接近上限时自动压缩，总结旧轮次并原样保留最新 20 000 token；也可随时 `/compact` | 项目文件（说明、技能）即上下文；没有自己的聊天记忆 |

其中 pi 和 DeepSeek Harness 保留原始会话，把较旧的片段就地替换为摘要。
personal-bot 则开一个新窗口，并让旧窗口保持可检索：轮换付出一次缓存未命中的代价，
但历史永远不会被反复总结，且始终是它发生时的样子。AstrBot 和 MaiBot 压缩单段对话，
并在上面加一层检索存储——AstrBot 的知识库、MaiBot 的 A-Memorix——
而 personal-bot 把记忆保持在助理自己写下并引用的笔记里。DeepSeek Harness 是五者中
唯一把记忆完全交给 MCP 服务端插件的。
