# 模型与 Jev

模型跑在 [pi](https://pi.dev) 上：**pi 支持的每一家服务商、每一个模型都能用**——
在 模型 页登录服务商，或填一个 key。模型页管三件事：主模型用哪个、Jev 的 key、
以及搜索用哪家。

## 主模型

模型目录来自 pi 的 agent 目录（内置的、pi.dev 目录、你自己的 `models.json`），
在机器人启动时拉取，之后每天自动刷新一次，`PI_OFFLINE=1` 时都不拉取；页头的 刷新目录 随时重新拉取一次。
一个 chip 显示当前主模型，点开是可搜索的列表。主模型**必须支持视觉输入**：
图片理解和表情选择都靠它；不支持的模型列在里面但是灰的，并说明原因。
chip 旁边的 思考 下拉选思考档位（关、极简、低、中、高、极高、最大）。

## Jev（出口审查）

Jev 是一个小一号、快一号的模型。它从不撰写回复，只回答是非题：要不要插话、
等多久再答、要不要引用、谁先回、这条气泡能不能发出、这个域名放不放行、
哪些笔记留下。每一轮发送前的检查都过它，所以它不可用时**隐私校验失败关闭，
一条消息都不会发**。

这一卡片显示它的状态（可用 / 还没有 key / 最近一次调用失败）和 设置 key /
更换 key 按钮。key 只写不读，保存在机器人侧，永远不会回到浏览器。

它的每一道判断的模式、阈值和额外判断在各自的页面上：[会话](./conversations) 的
回复时机 和 引用、[高级](./advanced) 的 排队、[安全](./safety) 的 出口审查。
新上线的判断默认 只记录不生效：日志里先看它会怎么做，再决定要不要信它。

## 服务商（LLM 登录）

列出 pi 注册的每一个服务商，带 pi 自己定义的登录方式：点进去，浏览器只转发 pi 的
提示，不存任何东西，中途可以取消，也可以登出。没有交互流程的服务商按 pi 的说明，
在 bot 容器的环境变量里配置。凭据由机器人侧保存。

## 搜索服务商

网页搜索和抓取走这里，key 同样只写不读。当前使用哪家在卡片里选用，和选主模型一样；
只登录了一家时不必选用，机器人直接用它（页面标成 未选用 并说明）。
DeepSeek 与上面的模型登录共用同一个 key：在这边登录即两边同时登录，登出同理。
