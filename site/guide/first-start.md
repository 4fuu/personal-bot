# 首次启动与扫码登录

任何镜像里都不包含 QQ。`qq` 容器在首次启动时安装固定的那个版本，来源必须是下面两者中的
**恰好一个**：

| 来源 | 怎么给 |
| --- | --- |
| 一个下载地址 | `.env` 里设置 `QQ_DEB_URL=https://example.com/QQ_3.2.34_260924_amd64_01.deb` |
| 一个你已经下载好的 deb | 在 `compose.yaml` 里把它挂载到 `/qq/QQ.deb`（取消两行注释），`QQ_DEB_URL` 留空 |

无论选哪一种，容器都会先校验文件的 sha256 与镜像内置的固定值是否一致，
**不一致就拒绝安装**，并报出它期望的版本号。安装结果落在 `qq_install` 卷里，
之后的启动会跳过安装。如果两个来源都没给、或者都给了，容器会说明情况并打印两种
正确的给法，而不是去猜。

::: warning 官方下载地址会返回 403
官方地址在没有签名的情况下不提供下载。请从镜像站下载文件，自己核对 sha256，
然后要么本地起一个服务（`python3 -m http.server` 加
`QQ_DEB_URL=http://127.0.0.1:8000/<文件>`，安装那一步用 `network_mode: host`），
要么直接挂载文件。
:::

## 扫码登录

1. `docker compose up -d` 之后打开 <http://localhost:8080>，用 `CONSOLE_PASSWORD` 登录。
2. 面板的 QQ 页（实时画面）显示的就是客户端自己的画面，二维码出现时用手机 App 扫它。
   **扫码是手动的，由你完成**——这是唯一必须你亲自动手的登录步骤。
3. 勾上 自动登录，之后的重启会自己恢复。
4. 扫码成功后，驱动程序读出数据库密钥，状态行的 `db.key` 变成 `"ok"`。

重启后客户端回到账号页时，驱动程序会自己点一次 登录，保存的会话直接恢复；
面板 QQ 页上的 登录 按钮是这一步的手动重试。只有重新创建过客户端配置
（删掉 `qq_profile` 卷）才需要再扫一次码。

## 密钥提取

数据库密钥让栈能解密客户端自己数据库的一份**私有副本**——消息 id、发送者、
@、引用、图片都从这份副本来，客户端的文件不被补丁、不被替换、也不被写入。
密钥只在你自己的机器上，`data/driver/secrets/db_key`，权限 0600。

提取在首次登录时进行一次，之后重启依然有效，不需要再提取。状态行显示
`db.key = "missing"` 表示还没完成，日志在宿主机的 `./logs/keyx.log`；显示
`"invalid"` 表示客户端换过密钥或副本对不上，按 QQ 页上给的步骤重新提取即可。

## 出问题时

| 现象 | 含义 |
| --- | --- |
| `error: no QQ source: set exactly one of ...` | `QQ_DEB_URL` 和挂载的 deb 都没给 |
| `error: sha256 mismatch: expected ... got ...` | 这个 deb 不是固定版本，换一个文件 |
| `error: both QQ_DEB_URL and the mounted deb ... are set` | 去掉其中一个 |
| 实时画面一直停在二维码 | 这是正常的：扫码登录是手动的，由你完成 |
| 面板页面返回 502 | driver 或 bot 还没起来，看 `docker compose logs qq bot` |

更多见 [排障](./troubleshooting)。
