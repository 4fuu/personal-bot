# 它是怎么工作的

模型是一个长期运行的 agent，每个账号一个会话，一次只处理一轮。这一页是机制概览；
完整的细节在仓库的
[docs/how-it-works.md](https://github.com/4fuu/personal-bot/blob/main/docs/how-it-works.md)
（[中文](https://github.com/4fuu/personal-bot/blob/main/docs/how-it-works.zh-CN.md)），
这里只链接、不复制。

## 什么开启一轮

- **消息**：私聊消息，或群里 @ 它、回复它、叫它名字的消息，按该会话的策略开启一轮；
  其他群消息在它决定插话时也可能开启一轮。
- **唤醒词**：它安静结束一轮时留下几个词，六小时内出现即开启新一轮。
- **`wait`**：它说"过一阵再来看"，一分钟到一天；到点会话带着最新消息重新打开。
- **定时任务**：在管理员私聊里设定，到点在指定会话开一轮，任务说明就是输入。
- **空闲轮**：设定的分钟数内一轮都没有时，它有一轮属于自己的时间，不属于任何会话。
  默认关闭，间隔在 [高级](./console/advanced) 设置。

## 一批消息，一次判断

消息先短暂合并：同一个人连着发时等得久一些，换人接话时短一些，
被 @ 时最多一秒，一整批最多约八秒。群里由 Jev 判断现在插话是否自然，
刚说过话时扣一点分、被 @ 时少扣一点。连着几批没开口后，下一次判断推迟，
消息暂存不丢。几个会话同时在等时，等太久的先回，Jev 也可以按紧急程度重排。

## 一个会话，滚动窗口

工作记忆不是一条无限增长的对话记录，而是一串带 token 预算的上下文窗口，
窗口在 token——而不是轮数——达到上限时被替换。窗口打开期间开头不变，
模型服务商的提示词缓存因此始终有效。窗口将满时，栈分阶段提醒它写笔记、准备交接；
到硬上限就自己轮换。新窗口以一段固定的开场笔记开头，带上活跃笔记、交接内容
和当前会话的最近消息；旧窗口不重放，但笔记、它自己的历史和聊天记录都还能检索到。

## 笔记是唯一的长期记忆

笔记由它自己写，每条带一段不超过 200 字的摘要和一份 token 预算；
每个新窗口保留一组活跃笔记（常驻的、这个窗口写改的、再按使用情况补满），
其余归档但可检索。笔记是只追加的，并锚在它来的那些消息和动作上，改过之后依然指得回出处。
在 [记忆](./console/memory) 页浏览它们。

## Jev：那个只答是非题的小模型

Jev 从不写回复，只给概率，栈拿概率和阈值比。它用在：要不要插话、等多久再答、
要不要引用、哪个会话先回、每条气泡发出前的审查、沙箱问到陌生域名时放不放行、
轮换时哪些笔记留下。每一处判断的模式——关闭 / 只记录不生效 / 启用——都在它自己的
页面上，新上线的判断先从 只记录不生效 开始：日志里先看它会怎么做。
