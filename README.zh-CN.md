## 项目架构

整套服务由四个容器组成，一套实例对应一个聊天账号：`qq` 容器在虚拟屏幕中运行官方桌面客户端，`bot` 容器运行模型，`console` 容器提供管理面板，模型的命令行操作则在独立的 `sandbox` 容器中执行。

```
┌──────────────────────────── 一套实例 = 一个账号 ────────────────────────────┐
│                                                                              │
│  桌面聊天客户端（官方原版、无头运行）                                        │
│    │ 写入数据库        ▲ 发送与按需下载      ▲ 自动点击“登录”               │
│    ▼                   │                     │                               │
│  私有解密副本 ────────▶ 驱动服务（HTTP + WebSocket）                        │
│                            │                        │                        │
│                            ▼                        ▼                        │
│                        console :8080              bot :8766                  │
│                        （管理面板、实时画面）     （模型、笔记、外发审核）   │
│                                                      │                       │
│                                                      ▼                       │
│                                                  sandbox :8791               │
│                                                  （以非特权用户执行命令）    │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **读取消息：** 客户端收到消息后会在几秒内写入本地加密数据库。驱动服务只复制该数据库并在私有副本上解密，从中读取真实的消息 ID、发送者、@提及、引用关系及本地缓存路径，不从客户端进程内拦截或监听消息流。
- **发送消息与下载媒体：** 文字、小黄脸表情、图片、表情包、文件、@提及和引用回复均调用客户端自身的发送接口，并由单一队列按接近真人的随机间隔控制节奏。由于桌面客户端平时只在打开会话窗口时才把收到的图片落盘，当模型需要查看某条消息的图片或文件而本地尚未缓存时，也会通过同一预加载库请求客户端下载该文件。
- **与客户端进程的交互：** 仅在首次登录时通过 `gdb` 断点提取一次数据库密钥（后续重启直接复用），并在启动时通过 `LD_PRELOAD` 注入一个小型动态库，用于发送消息、读取内置小黄脸表情表和按需下载指定消息的媒体文件。客户端自身的磁盘文件不做任何修改或替换。

### 聊天后端

聊天后端是**官方 Linux 版 QQ NT 桌面客户端**（固定为发布说明中指定的版本），在 `qq` 容器内的 TigerVNC 虚拟屏幕上原样运行。模型看到的聊天内容全部来自客户端本地数据库的解密副本（以及模型读取消息时按需触发的媒体下载），发出的每条消息也全部经由客户端自身的发送通道。

系统不订阅客户端内部事件流，也不使用任何第三方协议实现。管理面板中的“实时画面”直接转发客户端的屏幕画面，可用于扫码登录或随时查看客户端状态。

## 能做什么

- **自然聊天：** 自动回复私聊消息与群聊 @提及；在允许主动接话的群里，也能根据聊天氛围自主插话。每个会话的收发权限和说话方式都可以在面板中单独设置。
- **收发多种消息：** 支持发送文字、客户端内置小黄脸表情、表情包（遇到喜欢的会自动收藏）、图片和文件，支持引用回复与 @提及。
- **查阅聊天内容：** 支持翻阅和搜索历史消息、查看图片、下载群聊或私聊中的文件，以及读取语音消息和合并转发记录。
- **长期记忆：** 模型可自行创建和更新笔记，并按关键词或时间线检索过往窗口与自身操作记录。
- **延后跟进：** 支持等待一分钟至一天后再回来查看、留下六小时内有效的唤醒词、由管理员在私聊中设定定时任务，以及在长时间无对话时开启自由活动的“空闲轮”。
- **调用外部工具：** 支持网页搜索与网页正文读取；可在隔离沙箱中执行 Shell 命令和读写文件（沙箱仅能通过域名过滤代理访问外网）；支持通过脚本串联工具调用、安装和使用技能（Skills），以及连接 MCP 服务器（可在面板中按服务器或单个函数启停）。
- **Web 管理面板：** 集中管理实时画面与登录、会话策略、人设、记忆笔记、表情包、定时任务、模型与服务商登录、安全与网络规则、工作区（环境变量、Skills、MCP 服务器）、高级参数及实时日志。

## 它是怎么工作的

每个账号对应一个持续运行的模型会话，同一时间只处理一轮。新消息批次、唤醒词触发、等待到期、定时任务触发或空闲轮都会开启一轮。会话中连续到达的消息会先短暂合并成批；在允许主动接话的群里，先由 [Jev](https://typesafe.ai/) 评估此刻插话是否自然。如果一轮执行期间又有新消息到达，会在工具调用间隙直接交入当前轮次。

模型的工作记忆并非一条无限拉长的聊天记录，而是由一个个带 token 预算的上下文窗口接力组成。当窗口用量接近上限时，系统会分阶段追加提醒，引导模型更新笔记并写好四项交接备忘（当前话题、进展、待办、约定），随后轮换到新窗口。

笔记是模型唯一的长期记忆，每条笔记都带有一句简短摘要，并共享窗口的 token 预算。每次窗口轮换时，系统会自动挑出一组活跃笔记（管理员设为常驻的笔记、上一窗口新建或修改的笔记，以及按使用频率排序的常用笔记），把它们的摘要连同交接备忘和近期消息一起放入新窗口开头；其余笔记与历史窗口则归档保留，随时可按需检索。

[Jev](https://typesafe.ai/) 从不生成回复文本，只对结构化的是非题和分档打分题给出判断：例如群聊要不要插话、回复前要不要稍等片刻、多个会话排队时先回哪一个、回复时要不要带引用、即将发出的气泡是否泄露密钥或重复刷屏、沙箱请求的新域名是否放行，以及轮换窗口时哪些候选笔记在下一窗口更可能用到。

关于轮次、上下文与记忆机制的完整说明，以及与 AstrBot、MaiBot、DeepSeek Harness、pi 的横向对比，请参阅 [docs/how-it-works.zh-CN.md](docs/how-it-works.zh-CN.md)。

## 环境要求

- Linux x86_64，或运行 Linux 虚拟机的 macOS / Windows。
- Docker 24+ 或 Podman 4+（含 `compose`）。
- 约 2 GB 内存和 5 GB 磁盘空间（用于存放容器镜像与客户端配置数据）。
- 一个已有正常使用记录的 QQ 小号（切勿使用新注册的账号）。
- [pi](https://pi.dev) 支持的任意视觉模型服务商账号或 API key（如 Anthropic、OpenAI、OpenRouter、DeepSeek 等），以及用于外发审核与判断的 [Jev](https://typesafe.ai/) API key。

## 快速开始

```sh
git clone https://github.com/4fuu/personal-bot.git
cd personal-bot
cp .env.example .env
```

编辑 `.env`：设置管理面板密码 `CONSOLE_PASSWORD`，用 `openssl rand -hex 32` 生成三个内部通信令牌，并配置一种 QQ 安装包来源（见[首次启动](#首次启动)）。

```sh
mkdir -p data/driver/secrets data/bot/pi data/bot/secrets workspace logs
sudo chown -R 1000:1000 data/bot workspace logs
docker compose up -d
```

启动后在浏览器打开 <http://localhost:8080>，输入 `CONSOLE_PASSWORD` 登录，进入 **QQ** 页面，在实时画面中用手机 QQ 扫码登录。登录时请勾选**自动登录**，以便后续容器重启时自动恢复会话。

首次登录耗时较长：驱动服务需要通过调试器从客户端提取本地数据库密钥，在虚拟屏幕环境下实测最多约需 8 分钟。面板左侧状态栏的 **DB 密钥** 变为 **密钥正常**（**QQ** 页显示 **正常**）即代表提取完成。

若使用 Rootless Podman，请在创建目录后执行一次 `podman unshare chown -R 1000:1000 data/bot workspace logs`，代替上面的 `sudo chown`。

## 首次启动

容器镜像内不包含 QQ 安装包。`qq` 容器在首次启动时必须从以下两种来源中**二选一**安装指定版本的客户端：

| 安装来源 | 配置方式 |
| --- | --- |
| 下载地址 | 在 `.env` 中设置 `QQ_DEB_URL=https://example.com/QQ_3.2.34_260924_amd64_01.deb` |
| 本地 deb 安装包 | 在 `compose.yaml` 中取消 `/qq/QQ.deb` 挂载行的注释，并将 `QQ_DEB_URL` 留空 |

无论采用哪种方式，容器都会在安装前校验安装包的 SHA-256 摘要是否与镜像内置的固定值一致；**摘要不符会立即拒绝安装**并打印期望的版本号与摘要。安装完成后文件保存在 `qq_install` 卷中，后续启动直接跳过安装。如果未配置任何来源，或同时配置了两种来源，容器会报错退出并列出正确配置方法。

> 官方下载地址在缺少签名参数时会返回 `403`。若从镜像站下载安装包，请自行核对 SHA-256，然后直接在 `compose.yaml` 中将其挂载到 `/qq/QQ.deb`（或放在容器可访问的 HTTP 服务上并填入 `QQ_DEB_URL`）。

## 配置

[.env.example](.env.example) 中列出了所有环境变量及详细注释，核心配置如下：

| 变量 | 说明 |
| --- | --- |
| `CONSOLE_PASSWORD` | Web 管理面板的登录密码（唯一对外暴露端口的门禁） |
| `DRIVER_TOKEN`、`BOT_TOKEN`、`SANDBOX_EXEC_TOKEN` | 容器间内部鉴权令牌，分别用 `openssl rand -hex 32` 生成 |
| `QQ_DEB_URL` | 首次启动下载指定版本 QQ 安装包的 URL（挂载本地 deb 时留空） |
| `PI_OFFLINE` | 设为 `1` 时禁止从 `pi.dev` 拉取在线模型目录 |
| `KEYX_TIMEOUT_S` | 首次启动等待数据库密钥提取的秒数（默认 `900` 秒；超时后转入后台继续等待） |
| `PERSONAL_BOT_TAG` | 运行的镜像标签；留空默认使用 `latest`，也可填 `v2026.1025.0` 等标签固定版本 |

模型的日常运行设置——选用哪个主模型、允许参与哪些群聊与私聊、人设内容、笔记上限、沙箱可访问的域名等——均在 Web 管理面板中配置，无需修改 `.env`。

## 数据目录结构

| 宿主机路径 / 卷 | 容器内路径 | 存放内容 |
| --- | --- | --- |
| `./data/driver` | `/data/driver` | 提取出的数据库密钥（`secrets/db_key`，权限 `0600`）、解密后的消息镜像库（`mirror.db`）、驱动配置（`config.json`） |
| `./data/bot` | `/data/bot` | 模型状态与笔记数据库（`bot.db`）、模型登录凭据（`pi/auth.json`，权限 `0600`）、密钥目录（`secrets/`）、收藏与近期使用的表情包（`stickers/`） |
| `./workspace` | `/workspace` | 模型读写的工作区文件、已安装的技能、转存的聊天文件，以及超长工具输出的完整副本 |
| `./logs` | `/out` | `qq` 容器的运行诊断日志（`qq.log`、`keyx.log`、`novnc.log`） |
| `qq_profile`（命名卷） | `/home/qq/.config/QQ` | 客户端配置目录：登录态、加密数据库及图片缓存 |
| `qq_install`（命名卷） | `/opt/QQ` | 已安装的客户端程序文件 |

`./workspace` 仅由 `bot` 与 `sandbox` 两个容器共享。沙箱没有挂载任何其他目录，无法读取 `mirror.db`、`bot.db`、密钥或客户端文件；同时沙箱处于无外网路由的内部网络 `sandbox_net` 中，该网络内只有 `bot` 与 `sandbox`，因此沙箱访问互联网的唯一通道是 `bot` 提供的 HTTP(S) 出口代理。

`./logs` 下的诊断日志可能包含聊天原文，请妥善保管，排查问题对外贴出前请先删去个人隐私内容。

## 更新

```sh
docker compose pull
docker compose up -d
```

业务数据、客户端登录态（`qq_profile`）和已安装的客户端（`qq_install`）均保存在持久化目录与卷中，更新重建容器不会丢失数据。若新版本升级了固定的 QQ 客户端版本，需先删除 `qq_install` 卷再启动，以触发新版本客户端安装。

## 接入 OAuth MCP 服务器

模型支持以 MCP 客户端身份通过 OAuth 2.1 连接外部 MCP 服务器。支持 **Client ID Metadata Document**（CIMD）的授权服务器会直接把 `client_id` 当作一个公网 HTTPS 地址去拉取 JSON 元数据文档，从中读取客户端名称和允许的回调地址 `redirect_uris`。由于 `client_id` 必须与拉取该文档的 URL 完全一致，不同访问地址的面板需要对应各自的元数据文档。

**方式一：使用 Cloudflare Worker（推荐）。** 仓库 [`cimd-worker/`](cimd-worker/) 目录提供了一个零依赖的 Worker，将自定义 ID 和面板访问地址直接编码在 URL 路径中：

```
https://personal-bot-cimd.popoi.work/<id>/http/localhost:8080/mcp-client.json
```

当面板访问地址为 `http://localhost:8080` 时，访问上述 URL 会返回对应的元数据文档：

```json
{
  "client_id": "https://personal-bot-cimd.popoi.work/<id>/http/localhost:8080/mcp-client.json",
  "redirect_uris": ["http://localhost:8080/mcp/oauth/callback"]
}
```

请先用 `openssl rand -hex 16` 生成一个专属 `<id>`（16–64 位，仅限 `A-Z a-z 0-9 _ -` 且至少包含一个字母和一个数字），之后**固定使用同一个 ID**：它是注册到 MCP 服务端的 `client_id` 的一部分，也能避免同样通过 `http://localhost:8080` 访问面板的不同用户注册成同一个客户端。无论面板使用 `http`、`https` 还是本地回环地址均可正常工作。如需自行部署该 Worker：

```sh
cd cimd-worker
CLOUDFLARE_API_TOKEN=<具有部署 Worker 权限的令牌> npx wrangler deploy
```

**方式二：使用 GitHub Pages 静态文件。** 仓库根目录自带了一份 [`mcp-client.json`](mcp-client.json)，并随文档站发布在根路径：

```json
{
  "client_id": "https://4fuu.github.io/personal-bot/mcp-client.json",
  "redirect_uris": ["http://localhost:8080/mcp/oauth/callback"]
}
```

该静态文件默认假设你通过 `http://localhost:8080` 打开面板。如果你通过其他域名、隧道或端口访问面板，请改用上面的 Worker，或在 Fork 仓库后修改 `mcp-client.json` 中的 `client_id` 与 `redirect_uris` 并通过 GitHub Pages 发布。

**方式三：动态注册或使用预先注册的凭据。** 如果不想托管元数据文档，也可以在面板 **工作区** 页面添加 MCP 服务器时，将 **客户端注册** 设为 **动态注册**（需授权服务器支持）或 **预先注册的 client id**（手动填写在服务端注册好的 Client ID 与密钥）。

## 排障

| 现象 | 原因与处理方式 |
| --- | --- |
| `error: no QQ source: set exactly one of ...` | 未配置 `QQ_DEB_URL`，也未挂载 `/qq/QQ.deb`，请参见[首次启动](#首次启动) |
| `error: sha256 mismatch: expected ... got ...` | 提供的 deb 安装包不是当前版本要求的固定构建，请更换为正确版本的安装包 |
| `error: both QQ_DEB_URL and the mounted deb ... are set` | 同时配置了下载地址和本地挂载包，请只保留其中一种 |
| 实时画面一直停留在二维码界面 | 正常现象，首次登录需由你用手机 QQ 扫码确认 |
| 状态栏显示 **密钥缺失** | 数据库密钥仍在提取中，可查看宿主机 `./logs/keyx.log`；提取完成后状态会自动变为 **密钥正常** |
| 面板页面返回 `502` | `qq` 或 `bot` 容器尚未启动完毕，可执行 `docker compose logs qq bot` 查看启动日志 |
